# Upload Key Setup (Google Play App Signing)

BTC Field App is published with **Google Play App Signing**:

- **App signing key** — generated and held by Google. It signs the APKs users install from Play. We never see it.
- **Upload key** — generated by us, kept offline. It signs the AAB we upload; Google verifies it and re-signs.

If the upload key is lost or leaked, Google Play support can reset it (see
[KEY_BACKUP_AND_RECOVERY.md](KEY_BACKUP_AND_RECOVERY.md)). The app signing key is never at risk.

## App identity (permanent)

| Field | Value |
|---|---|
| applicationId | `ge.btc.field_app` (approved by owner — cannot change after first upload) |
| Version source | `pubspec.yaml` → `version: <versionName>+<versionCode>` |

## Upload key parameters

| Parameter | Value |
|---|---|
| Keystore | `~/.android-keys/btc-field-app/upload-keystore.jks` (PKCS12, outside the repo, mode `600`) |
| Alias | `upload` |
| Algorithm | RSA 4096, SHA256withRSA |
| Validity | 10,000 days (until 2054-03-19) |
| Subject | `CN=BTC Field App Upload Key, O=Georgian Cartographers Association, L=Tbilisi, C=GE` |
| Credentials | `~/.android-keys/btc-field-app/credentials.properties` (mode `600`) |
| Public certificate | `~/.android-keys/btc-field-app/upload_certificate.pem` |

Upload certificate fingerprints (public — safe to share, used to confirm the right key):

```
SHA1:   82:05:8C:37:F0:30:8F:C6:7C:6D:5E:E9:F0:E1:0D:56:81:C1:42:97
SHA256: F8:20:11:52:8D:5A:D7:62:36:AA:A1:F3:99:3B:95:68:FB:85:AD:EB:05:5D:FB:58:E4:2B:17:34:2D:8C:83:2F
```

## How the key was generated

The password was generated by `openssl rand` inside the shell and written straight to the
credentials file; it was never printed or typed into any chat or tool output.

```bash
umask 077
K=~/.android-keys/btc-field-app
mkdir -p "$K"
export KS_PASS=$(openssl rand -base64 33 | tr -d '/+=\n' | cut -c1-40)
keytool -genkeypair -v -keystore "$K/upload-keystore.jks" -storetype PKCS12 \
  -alias upload -keyalg RSA -keysize 4096 -sigalg SHA256withRSA -validity 10000 \
  -dname "CN=BTC Field App Upload Key, O=Georgian Cartographers Association, L=Tbilisi, C=GE" \
  -storepass:env KS_PASS -keypass:env KS_PASS
keytool -exportcert -rfc -alias upload -keystore "$K/upload-keystore.jks" \
  -storepass:env KS_PASS -file "$K/upload_certificate.pem"
unset KS_PASS
```

## How Gradle reads the credentials

[`android/app/build.gradle.kts`](../../android/app/build.gradle.kts) looks for, in order:

1. `android/key.properties` (git-ignored):

   ```properties
   storeFile=/home/<user>/.android-keys/btc-field-app/upload-keystore.jks
   keyAlias=upload
   storePassword=<secret>
   keyPassword=<secret>
   ```

   Create it by copying the credentials file:

   ```bash
   install -m 600 ~/.android-keys/btc-field-app/credentials.properties android/key.properties
   ```

2. Environment variables, when `key.properties` is absent:
   `BTC_UPLOAD_STORE_FILE`, `BTC_UPLOAD_STORE_PASSWORD`, `BTC_UPLOAD_KEY_ALIAS`, `BTC_UPLOAD_KEY_PASSWORD`.

If neither is present, **release builds fail** with an explicit error (there is no silent fallback
to the debug key). Debug builds never need the upload key.

## Rules

- Never commit the keystore, `key.properties`, or `credentials.properties` (`.gitignore` covers them).
- Never put passwords in Gradle files, CI logs, issues, chat, or email.
- Never upload the upload keystore to GitHub (including Actions secrets), Google Drive, or any AI tool.
- The public certificate (`upload_certificate.pem`) is not secret; Google Play may ask for it during an upload-key reset.

## First Google Play upload

1. Play Console → create the app with package `ge.btc.field_app`.
2. Release → Setup → App integrity → keep **"Use Google-generated key"** (Play App Signing).
3. Upload the signed AAB (see [ANDROID_RELEASE_BUILD.md](ANDROID_RELEASE_BUILD.md)). The first upload registers this upload key.
4. In App integrity, confirm the **Upload key certificate** SHA-256 matches the fingerprint above.
5. Copy the **App signing key** SHA-1/SHA-256 from App integrity into Firebase (project settings → Android app) if Firebase services that check signatures are used.

## Note on GitHub Releases APKs

`.github/workflows/release.yml` signs sideload APKs with a separate key from `KEYSTORE_*` Actions
secrets. That key is **not** the Play upload key and must stay separate. APKs signed with it cannot
be updated in place by the Play Store version (different signature); users must uninstall first.
